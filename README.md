# KeibaScope

KeibaScope は、中央競馬（JRA）のレースについて、各馬の勝率と買い目を出す個人用のデスクトップアプリである。
出馬表とオッズは netkeiba から取得し、過去の成績と調教は JRA-VAN Data Lab のデータを手元のデータベースに入れて使う。
Tauri v2（Rust）と React で作っている。

## 勝率の出し方

勝率は、手元に JRA-VAN のデータベースがあるかどうかで、二つのモデルを使い分ける。

データベースがあるときは、2021〜2025年の JRA 平地 16,650 レースで当てはめたモデルを使う。
各馬について、そのレースより前の日付の成績と調教だけから 38 個の特徴量（スピード指数、上がり、着差、騎手・調教師の成績、坂路とウッドの調教タイムなど）を作る。
単勝オッズから求めた市場の勝率と特徴量を一つの多項ロジットに入れ、1着の結果に当てはめた係数で勝率を出す。
発売前でオッズがないレースでは、オッズを使わずに当てはめた係数で計算する。

データベースがないときは、netkeiba の過去5走から作る5項目のスコア（能力、時計、適性、騎手・枠、展開）で計算する。
画面のレース名の横に、どちらのモデルを使ったかを「JRA-VANモデル」「簡易モデル」と表示する。

2着・3着の確率は、勝率から Harville モデルで出す。
人気馬の2・3着を過大に見積もる Harville の偏りは、2着の段で勝率の 0.9 乗、3着の段で 0.7 乗を使って補正している。
馬連・ワイド・3連複の的中率もここから計算し、JRA のレースでは実オッズ、取れない券種では推定オッズ（画面に「推定」と表示）と掛け合わせて期待値を出す。

## このモデルで分かっていること

時系列で学習期間と検証期間を分けた検証（後半 8,324 レース）では、市場の勝率にこのモデルの特徴量を足すと、1着の対数損失が 0.0032 小さくなった（95% 区間 [−0.0061, −0.0004]）。
市場は、前走の好走や人気、上位騎手を買いすぎ、騎手の乗り替わりによる格上げ、距離や芝・ダートの変更、調教のラスト1Fの速さを軽く見る傾向があった。

ただし、この改善で利益が出るわけではない。
期待値 1.0 以上の単勝を買った場合の回収率は 94.0%（2,622 点）で、控除率を越えていない。
しかもこの数字は確定オッズで計算しており、実際に買える締め切り前のオッズでは、さらに下がる可能性がある。
モデル単体（市場の勝率を使わない場合）の精度は、単勝オッズよりかなり低い。

検証の手順、採用の基準、試して採用しなかった特徴量は [docs/BACKTEST.md](docs/BACKTEST.md) にまとめている。
2026年のレースは最終判定用に取ってあり、開発には使っていない。

## 動かすのに必要なもの

アプリ本体のビルドには Node.js（npm）と Rust が要る。
JRA-VAN のデータを使う場合は、さらに次の三つが要る。

- JRA-VAN Data Lab の利用キー
- JV-Link をインストールした Windows PC（JV-Link は Wine 上では初期化の段階で落ちるため、Mac では動かない）
- Windows で取り出したデータを Mac に渡す手段（USB、クラウドなど）

## 起動

```
npm install
npm run tauri dev
```

配布用のアプリにするときは `npm run tauri build` を使う。

## JRA-VAN データの用意と更新

JRA-VAN のデータは、Windows で取り出して Mac のデータベースに取り込む。
取り出しには、このリポジトリの Windows 用ツール（[tools/jvlink-dump](tools/jvlink-dump/README.md)）を使う。

最初の一回は、Windows で全期間を取り出す。
`build.bat` でツールを作り、`JvDump.exe setup` で利用キーを設定してから、`dump_all.bat` を実行する。
2021年以降のレース・調教・マスタ・血統を取り出し、数時間かかることがある。

以後は週に一度、`update_all.bat` で前回の続きだけを取り出す。
`register_weekly_task.bat` を実行すると、毎週火曜の朝に自動で動く。

取り出した `out` フォルダは Mac に移し、アプリの「回収率」画面の「JRA-VAN データ」から取り込む。
コマンドで取り込むこともできる。

```
cd src-tauri
cargo run --release --example jv_ingest -- <データベースのパス> <out フォルダのパス>
```

取り込みは、ファイルごとに前回どこまで読んだかを覚えていて、追記された分だけを読む。
同じレースが段階ごと（出走馬名表、出馬表、成績）に何度届いても、より確定に近いものだけを残す。
何度実行しても結果は変わらない。

アプリが使うデータベースは、環境変数 `KEIBA_DB` で指定したファイル、なければアプリのデータフォルダの `keiba.db` である。

## 画面の表示について

出馬表の画面では、予想順に各馬のゼッケン（枠の色と馬番）を並べ、上に印、下に指数を出す。
推奨の買い目に入っている馬は、ゼッケンを紫の枠で囲む。

画面に出る注記の意味は次のとおりである。

- 「推定」：実オッズが取れなかった券種のオッズ。単勝オッズから計算した値で、実際の配当とは異なる。
- 「確定後の予想・集計外」：結果が出たあとに作った予想。保存しても回収率には数えない。
- 「馬番は仮」：木曜の出走馬名表の段階で、まだ馬番が決まっていないレース。番号は並び順の仮のもので、買い目の番号もそのままでは使えない。

「回収率」の画面は、発走前に保存し、結果照合まで済んだ予想だけで回収率を計算する。
結果照合では、保存したときの買い目をそのまま公式の払戻と照らし合わせる（予想を作り直すことはしない）。

## 検証を手元で再現する

データベースを用意したうえで、次のコマンドで検証をやり直せる。

```
cd src-tauri
cargo run --release --example jv_model -- <データベースのパス>
```

アプリが使う係数を作り直すときは、`--export src/jv_coef.rs` を付ける。
バックテストとアプリは同じ特徴量のコードを使うので、作り直した係数はそのままアプリに反映される。

## データの扱い

netkeiba と JRA-VAN のデータは、このリポジトリに入れていない（リポジトリは公開しており、データの再配布になるため）。
バックテスト用のデータは `backtest/` に置き、Git の対象から外している。

バックテスト用に netkeiba からまとめて取得するときは、1並列・1.5秒間隔に抑えている。
5並列で取得したときに、race.netkeiba.com から一時的にアクセスを止められたためである。
netkeiba と JRA-VAN の利用規約で、自動取得や外部サービスへの保存がどこまで認められるかは確認できていないので、利用する前に各自で確かめてほしい。
