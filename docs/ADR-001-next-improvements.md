# ADR-001: 次に取るデータとロジック改善の優先順位

**Status:** Proposed
**Date:** 2026-11-14
**Deciders:** 持ち主（買い方と、JRA-VAN 試用期間 12/11 までの使い道を決める）

## Context

いまのモデルは、市場（単勝オッズを γ 乗で補正）に自前の 40 列を足した 1 着の多項ロジットで、2012〜2025 年の JRA 平地 46,585 レースで当てはめている。市場との差は −0.0032 [−0.0061, −0.0004]（確かに良いが小さい）。

これまでの検証（docs/BACKTEST.md）で分かっていること:

- 同じ種類の情報を増やしても伸びない。血統・調教の詳細・道悪の実績は上積みなし、学習年数も 8 年で頭打ち（11 年 − 8 年 = −0.00008 [−0.00045, +0.00030]）。
- 買い方で検証を通ったのは単勝の期待値 1.0 以上だけ。確かめる期間で 103.1% [90%, 117%]（確定オッズ）。
- 組み合わせ馬券は、的中確率の較正は合っているのに、期待値 1.0 以上を買うと 67〜79%。期待値が高く見える組み合わせほど、モデルの誤差が市場とずれた側に出ている（推測）。
- 回収率はすべて確定オッズで計算している。締め切り前に買えるオッズの記録は 11/14 に始めたばかり。
- 2026 年は最終判定用で、まだ使っていない。

制約: 一人で使う道具。JRA-VAN は試用期間（12/11 まで）で、GitHub Actions の枠にも限りがある。検証は事前に手順を書き、一度だけ回す。

## Decision

次の順に進める。

1. **組み合わせの確率を、組み合わせのオッズ（市場）とモデルを混ぜて出す**（ロジック、手元のデータだけで検証できる）。
2. **期待値に誤差の幅を付け、買う判断を幅の下側で行う**（ロジック、手元のデータで検証できる）。
3. **締め切り前オッズと、オッズの動きを集める**（データ。時間をかけてためる。過去分が取れるかは要確認）。
4. 票数（プールの大きさ）は後回し。新しい特徴量の追加と、モデルの形の変更はやらない。

## Options Considered

### Option A: 組み合わせの確率を市場と混ぜる

いまは、組み合わせの確率を「モデルの勝率 → 補正つき Harville」で作り、それを組み合わせのオッズと掛けて期待値にしている。市場は組み合わせごとに独自の情報（ほかの人が組み合わせとしてどう見ているか）を持っているのに、それを使っていない。単勝で市場とモデルを混ぜたのと同じ考え方で、組み合わせのオッズから出した確率とモデルの確率を、ロジットの空間で混ぜる。混ぜる重みは選ぶ期間で当てはめる。

| 観点 | 評価 |
|---|---|
| 手間 | 中。組み合わせのオッズ（O2・O3・O5）と払戻（HR）は、`--bets` / `--plan` ですでに読めている |
| 費用 | 新しいデータは不要 |
| 効果の見込み | 中〜大。組み合わせで負けている原因（勝者の呪い）に直接効く |
| 検証のしやすさ | 高。選ぶ期間 2016〜2021 / 確かめる期間 2022〜2025 の枠組みをそのまま使える |

**良い点:** いちばん大きく負けている所に効く。手元のデータで閉じる。アプリの「買い目全体の評価」と期待値の表示が、そのまま正直になる。
**悪い点:** 組み合わせのオッズは確定オッズしかなく、締め切り前の値とのずれは残る。市場に寄せるほど期待値 1.0 以上の組み合わせは減り、買えるものがほとんど残らない可能性がある（それ自体が正しい答えかもしれない）。

### Option B: 期待値に幅を付けて、下側で判断する

勝率の推定には誤差があり、期待値 = 確率 × オッズは、確率が 1 ポイントずれるだけで大きく動く。係数のブートストラップ（または区間ごとに当てはめた係数のばらつき）から勝率の幅を出し、期待値の幅として表示する。買う判断を「期待値の下側 ≥ 1.0」にしたときの成績を、事前に決めて一度だけ検証する。

| 観点 | 評価 |
|---|---|
| 手間 | 低〜中 |
| 費用 | 新しいデータは不要 |
| 効果の見込み | 中。点数は減るが、外れの多い「見かけだけ高い期待値」を落とせる |
| 検証のしやすさ | 高 |

**良い点:** 表示が正直になる（数字の過信を防ぐ）。A と組み合わせられる。
**悪い点:** 買う点数が減り、回収率の区間はむしろ広がる。単勝のルールはすでに確かめる期間を使い切っているので、新しいルールは 2026 年の最終判定まで本当の評価ができない。

### Option C: 締め切り前オッズとオッズの動き

確定オッズで計算した回収率は、実際に買えるオッズより有利に出ている可能性がある。締め切り 30・10・3 分前のオッズを毎週ためて、実際に買える条件で単勝のルールを確かめ直す。あわせて、オッズの動き（前売りから締め切りまでの変化）が特徴量になるかを見る。パリミュチュエルの研究では、締め切り間際の資金の流れに情報があるとよく言われる（このデータで確かめたことはない）。

| 観点 | 評価 |
|---|---|
| 手間 | 低（記録の仕組みはある）。過去分を JRA-VAN の時系列オッズ（`JvDump rt 0B41`）から取るなら中 |
| 費用 | 記録は手元の Mac で動く。過去分の取得は Actions と試用期間を使う |
| 効果の見込み | 検証の正しさには必須。特徴量としての効果は未知 |
| 検証のしやすさ | 低（たまるまで数か月） |

**良い点:** 今の検証で一番大きい弱点（確定オッズ）を埋める唯一の方法。
**悪い点:** 時間がかかる。速報系の時系列オッズが、過去何年分までさかのぼって取れるかは確かめていない（要確認）。

### Option D: 票数（プールの大きさ）

自分の賭け金でオッズが下がる影響と、プールの薄い組み合わせの信頼度に使える。

| 観点 | 評価 |
|---|---|
| 手間 | 中 |
| 効果の見込み | 小。100 円単位の買い方では影響はわずか（推測） |

**良い点:** 理屈として正しい。**悪い点:** いまの買い方では効く場面がほとんどない。

### Option E: 特徴量の追加・モデルの形の変更（やらない）

コース別の騎手成績、交互作用、勾配ブースティングなど。これまでの探索では、二乗・交互作用・市場の非線形はどれも ±0.0001 程度で、血統・道悪・年数も頭打ちだった。同じ公開情報をこれ以上こねても、市場に織り込まれている可能性が高い。

## Trade-off Analysis

- **いますぐ検証できるか**: A と B は手元のデータで閉じる。C は時間がかかる。だから A・B を先にやり、C は並行してためる。
- **どこで負けているか**: 損の大部分は組み合わせ馬券（67〜79%）と、確定オッズの楽観。A は前者、C は後者に効く。B は両方の表示を正直にする。
- **検証の予算**: 単勝のルールは確かめる期間を使い切っている。A は組み合わせについての新しい問いなので、選ぶ期間・確かめる期間をまだ使える。B を新しい買い方として採るなら、本当の評価は 2026 年の最終判定になる。
- **データの予算**: 試用期間の残りで取る価値があるのは、C の過去の時系列オッズだけ（取れる範囲が分かれば）。昔の RACE・調教は取らない（学習年数の検証で頭打ち）。

## Consequences

- 組み合わせ馬券の期待値が、市場の見方を含んだものになる。期待値 1.0 以上の組み合わせはほぼなくなる見込みで、アプリの表示もそれに合わせて控えめになる。
- 期待値が幅つきで表示され、「149%」のような点の値を過信しにくくなる。
- 締め切り前オッズがたまれば、単勝のルールを「実際に買える条件」で確かめ直せる。結果が悪ければ、おすすめの印を外す判断が必要になる。
- 見直す時期: 締め切り前オッズが 3 か月分たまった時点（2027 年 2 月ごろ）と、2026 年の最終判定のとき。

## Action Items

1. [ ] A の検証計画を BACKTEST.md に書く（混ぜ方、重みを当てはめる期間、採用の条件）。結果を見る前に commit する
2. [ ] A を `jv_model --combo-market` として実装し、一度だけ回す。通ればアプリの組み合わせの確率と期待値に入れる
3. [ ] B の幅の出し方（係数のブートストラップ）を決め、まず表示だけ入れる。買う判断に使うかは別に計画する
4. [ ] JRA-VAN の時系列オッズが過去どこまで取れるかを、1 レース分だけ `JvDump rt 0B41` で確かめる（12/11 までに）
5. [ ] 締め切り前オッズの記録を毎週末続ける（`backtest/odds/run_weekend.sh`）
6. [ ] 2026 年の最終判定の日付と手順を決める
