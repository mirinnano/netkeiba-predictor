# 予測の検証手順

市場（単勝オッズ）に勝てるかを、後から都合よく解釈できない形で確かめるための取り決め。
結果を見てからこの文書を書き換えない。変えるときは理由と日付を「変更履歴」に残す。

## 問い

**オッズに入っていない情報を足すことで、締め切り前のオッズで買って控除率を越えられるか。**

「市場より正確か」ではなく「市場に足したときに良くなるか」を見る。
市場に足して良くならない情報は、すでにオッズに織り込まれている。

## データ

| データ | 置き場所 | 取り方 |
|---|---|---|
| 確定レース（出馬表・過去5走・確定オッズ・払戻） | `backtest/races_<年>.jsonl` | `cargo run --example collect_backtest -- <出力> <年> <月あたり日数> <並列数>` |
| 馬ごとの競走成績（展開・位置・上がり） | `backtest/horses.jsonl` | `WORKERS=1 cargo run --example collect_horses -- <出力> <races.jsonl>...` |
| 締め切り前オッズ（30・10・3分前） | `backtest/odds/odds_<日付>.jsonl` | `cargo run --release --example record_odds -- <出力> <日付>` |

`backtest/` はリポジトリに入れない（netkeiba のデータのため）。

netkeiba への負荷について：5並列で race.netkeiba.com から一時的にブロックされた（2026-11-12）。
並列は 1〜3 に留め、各ワーカー 1.5〜2 秒間隔、失敗が続いたら止める。

## JRA-VAN データの保管と更新（SQLite）

```
Windows: update_all.bat（差分だけ取得）
   ↓ out フォルダを Mac の backtest/jvdata/out へ上書きコピー
Mac:     cargo run --release --example jv_ingest -- backtest/keiba.db backtest/jvdata/out
   ↓
Mac:     cargo run --release --example jv_model -- backtest/keiba.db
```

- 元データは JvDump の出力（追記だけのテキスト）。`keiba.db` はそこから作る解析用の写しで、壊れても約13秒で作り直せる。
- 取り込みはファイルごとに前回読んだバイト位置を覚え、追記分だけを読む。同じレース・同じ馬はキーで1件にまとめ、
  より確定に近いデータ区分だけが上書きする。データ区分 0（提供側の取り消し）は DB からも消す。
- 確認済み（2026-11-13）: 2段階で取り込んだ結果と一括で取り込んだ結果は races・runners とも全行一致。
  追記なしで再実行すると何も変わらない。DB から読んだ `jv_model` の結果はファイルから読んだときと同じ。
- 中止・地方・海外のレースは races に入らない（その出走 439 件は runners にだけ残るが、読み出しは races と結合するので使われない）。

### バックアップ

- データ本体は非公開リポジトリ `mirinnano/keiba-data` のリリースに置く（このリポジトリは公開なので、データは入れない）。
- 2026-11-13: タグ `data-20261113`（JvDump の出力・坂路・netkeiba のデータ。SHA-256 一致を確認済み）。
- 復元手順はそのリポジトリの README にある。`keiba.db` は元データから作り直す。
- 更新したら、新しい日付のタグで差分ではなく丸ごと置く（2GB/ファイルまで）。

## 開発用と最終判定用の分け方

- **開発用**：2021〜2025年のレース。特徴量・正則化・閾値の選び直しはここでだけ行う。
- **最終判定用（ホールドアウト）**：2026年1月以降のレース。モデルを決め切るまで**集めない・見ない**。
  決めたら一度だけ集めて一度だけ評価する。結果が悪くても、そのデータで作り直してもう一度、はしない。
- 締め切り前オッズの記録（2026-11-14〜）は最終判定用の期間にあたる。記録はするが、最終判定まで中身を評価に使わない
  （取れているかの件数確認だけはしてよい）。

## 開発用での評価（`cargo run --release --example backtest -- <races.jsonl>... [--horses <horses.jsonl>]`）

- 日付順に8区間に分け、k 区間目まで学習・k+1 区間目で検証（k=4..7）。
- 基準タイム・騎手・ペース基準は学習側の過去走だけ、父の成績はそのレースより前の結果だけで作る。
- 主な指標は1着の対数損失。比べる相手は「市場（γ補正）」= 単勝オッズの勝率を γ 乗したもの。
- 特徴量を採用する条件：**市場＋特徴量が市場（γ補正）より、4区間すべてで良い**こと、かつ
  **検証全区間をまとめたレース単位の対応のあるブートストラップで、差の95%区間が 0 を含まない**こと（2026-11-12 追加）。
- 回収率は参考値。確定オッズで計算しているので、実際より有利に出ている可能性がある。

## 最終判定（ホールドアウトで一度だけ）

次をすべて満たしたら「市場に勝てる見込みがある」と言ってよい。

1. 市場＋モデルの1着対数損失が、市場（γ補正）より小さい。
2. 締め切り3分前のオッズで「期待値 ≥ 閾値」の単勝を買ったときの回収率について、
   ブートストラップ（レース単位で再標本化）の95%区間の下限が 100% を超える。閾値は開発用データで先に決めておく。
3. 2 の買い目が 1,000 点以上ある。

満たさなければ「公開情報のこの使い方では勝てない」が結論。それも記録する。

## 開発用データでの所見（2023〜2025年 1518レース, 2026-11-12 時点）

- 1着の対数損失（4区間平均）: 市場 1.8783 / 市場（γ補正）1.8767 / 市場＋モデル 1.8746。市場＋モデルは4区間すべてで市場（γ補正）より良い。
- ただし市場と一緒に当てはめたモデルの重み δ は **4区間すべてで負（−0.09〜−0.10）**。
  市場を知った上では、モデル（＝公開されている成績の要約）が高く評価する馬ほど買われすぎている、という意味。
  特徴量ごとに見ても、能力・適性・斤量・指数（最高）は負、指数（平均）・騎手・父・前走の着差・前走人気は正で、区間をまたいで符号が揃う。
- γ は 1.09〜1.11（>1）。単勝オッズのままだと人気馬をやや低く、人気薄をやや高く見ている。
- 期待値 ≥ 1 の馬は検証区間に一頭もいない。期待値 ≥ 0.8 の単勝の回収率は 85.0%（2,030点, 確定オッズ）。
- 当日の馬場の偏り（同日・同場の前のレースの内外・前後）は上積みなし。
- **訂正（同日, 対応のあるブートストラップ）**: 検証全区間 756 レースをまとめると、
  市場＋モデル − 市場（γ補正）= −0.0021、95%区間 [−0.0054, +0.0014]。**0 を含むので有意ではない**。
  「4区間すべてで良い」は弱い証拠だった。γ補正も [−0.0043, +0.0010] で有意ではない。
- 1〜3着の順序（Plackett-Luce）で学習すると、1着の対数損失は有意に悪化した（+0.022 [+0.010, +0.036]）。
  2・3着を同じ効用で扱うと、2・3着の決まり方の違い（Harville の偏り）を勝率側に持ち込むため。採用しない。
- 0.002 程度の差を検出するには、検証用のレースが今の約4倍（3,000レース程度）必要。
  採用条件に「対応のあるブートストラップの95%区間が 0 を含まない」を加える。

## JRA-VAN の全レースでの所見（2021〜2025年 平地 16,650レース, 2026-11-13）

- データ: JvDump で取得した RA/SE を `jv_build` で重複除去（確定成績を優先）。netkeiba の 21,016 頭と突き合わせ、
  着順・タイム・単勝オッズ・枠・上がり3F は 100%、斤量 99.99% 一致。
- 検証は時系列8区間のうち後半4区間（8,324 レース）。95%区間の幅は約 ±0.0004 で、netkeiba の標本（±0.0035）より約10倍細かい。
- **JRA-VAN のマイニング予想（順位・予想タイム）は市場に上積みなし**: +0.0000 [−0.0004, +0.0005]。係数はわずかに負。
  JRA-VAN 利用者向けの予想も、すでにオッズに織り込まれている。
- 期待値 ≥ 1.0 の馬は検証区間に一頭もいない（市場＋マイニングでも同じ）。

## 自前の特徴量（JRA-VAN 全レース, `jv_model`, 2026-11-13）

- 30個の特徴量を、そのレースより前の日付のデータだけで作った（日付ごとに特徴量を作ってから、その日の結果を履歴に足す）。
  基準タイムとペースの基準は 2021年だけで作る。過去走のある馬は 86.6%（2021年初めは履歴がない）。
- 1着の対数損失（検証 8,324 レース）: 市場 1.9117 / 市場（γ補正）1.9113 / モデルのみ 2.1341 / **市場＋全特徴量 1.9088**。
- **市場＋全特徴量 − 市場（γ補正）= −0.0026 [−0.0048, −0.0004]**。4区間すべてで良く、95%区間が 0 を含まない。
  採用条件を初めて満たした。
- グループ別で有意: 着順・着差 −0.0016 [−0.0028, −0.0005]、その他（馬齢・馬番・脚質・同場/同距離成績）−0.0017 [−0.0032, −0.0004]。
  時計・上がり展開・過去人気・クラス・騎手調教師・状態ローテは単独では有意でない。
- 市場と一緒に当てはめた係数は大半が4区間で符号一致。市場は「前走の好走・前走の人気・高齢・上位騎手・同場/同距離の好成績」を
  買いすぎ、「騎手の格上げ・クラス変化・休み明け・距離/芝ダ変更・馬体重・上がり・ブリンカー」を軽く見ている。
  つまり、直近の成績と評判に反応しすぎ、変化を織り込み切れていない。
- ただし儲かる水準ではない: 期待値 ≥ 1.0 の単勝 88.6%（1,233点）、≥ 1.1 で 97.6%（170点）。どちらも確定オッズ。
- 注意: グループ別の比較は8つ同時に見ているので、単独で有意なグループには多重比較の分だけ割り引いて考える。
  主要な比較（市場＋全特徴量）は事前に決めていたもの。

### 調教を追加（坂路 HC 277万件・ウッド WC 80万件, 2026-11-13）

- レース前日までの14日間の調教から、坂路/ウッドの4F・ラスト1F（2021年のトレセン・コース別中央値との差）、本数、
  最終追い切りからの日数とラスト1F を作った（計38特徴量）。
- **市場＋全特徴量 − 市場（γ補正）= −0.0032 [−0.0061, −0.0004]**（調教なしは −0.0026）。
- 調教だけを足すと −0.0009 [−0.0028, +0.0009] で単独では有意でない。
  ただし係数は4区間で符号が揃い、**ラスト1F が速い馬は軽視され（+0.08〜+0.10）、4F 全体が速い馬は買われすぎ**ている。
- 単勝の回収率（確定オッズ）: 期待値 ≥ 1.0 で 93.6%（2,639点）、≥ 1.1 で 97.1%（545点）。まだ 100% に届かない。

### 調教の詳細を試して不採用（2026-11-13）

- 追加した5つ: 最終追い切りの加速、自己比ラスト1F（15〜120日前の中央値との差）、併せ馬の目安、28日間の本数、最終が坂路か。
- 係数は4区間で符号が揃ったが、**予測は有意に悪化**: (+調教詳細) − 全特徴量 = +0.0007 [+0.0001, +0.0015]。
  符号が揃うことは、検証で良くなることの証明にならない（係数の推定ぶれが増えて、検証では損をした）。採用しない。
- 途中、比べる列を取り違えて「詳細は有意に良い」と出した。比較の添字を直して確認した（`jv_model.rs` にどの列が何かを明記）。

## 既知の弱点

- 開発用の回収率は確定オッズで計算している（締め切り前オッズの記録は 2026-11-14 から）。
- レースは各月15日前後の土日、月1〜2日分だけを取っている。季節や開催場の偏りは未確認。
- 開発用データで何度も選び直しているので、開発用の数字は楽観的に出ていると考える。
- 買い目の組み方（◎-○ など）と金額の配分は手で決めたまま。データで確かめたのは単勝だけ。
