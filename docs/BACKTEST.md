# 予測の検証手順

市場（単勝オッズ）に勝てるかを、後から都合よく解釈できない形で確かめるための取り決め。
結果を見てからこの文書を書き換えない。変えるときは理由と日付を「変更履歴」に残す。

## 問い

**オッズに入っていない情報を足すことで、締め切り前のオッズで買って控除率を越えられるか。**

「市場より正確か」ではなく「市場に足したときに良くなるか」を見る。
市場に足して良くならない情報は、すでにオッズに織り込まれている。

## データ

| データ | 置き場所 | 取り方 |
|---|---|---|
| 確定レース（出馬表・過去5走・確定オッズ・払戻） | `backtest/races_<年>.jsonl` | `cargo run --example collect_backtest -- <出力> <年> <月あたり日数> <並列数>` |
| 馬ごとの競走成績（展開・位置・上がり） | `backtest/horses.jsonl` | `WORKERS=1 cargo run --example collect_horses -- <出力> <races.jsonl>...` |
| 締め切り前オッズ（30・10・3分前） | `backtest/odds/odds_<日付>.jsonl` | `cargo run --release --example record_odds -- <出力> <日付>` |

`backtest/` はリポジトリに入れない（netkeiba のデータのため）。

netkeiba への負荷について：5並列で race.netkeiba.com から一時的にブロックされた（2026-11-12）。
並列は 1〜3 に留め、各ワーカー 1.5〜2 秒間隔、失敗が続いたら止める。

## JRA-VAN データの保管と更新（SQLite）

```
Windows: update_all.bat（差分だけ取得）
   ↓ out フォルダを Mac の backtest/jvdata/out へ上書きコピー
Mac:     cargo run --release --example jv_ingest -- backtest/keiba.db backtest/jvdata/out
   ↓
Mac:     cargo run --release --example jv_model -- backtest/keiba.db
```

- 元データは JvDump の出力（追記だけのテキスト）。`keiba.db` はそこから作る解析用の写しで、壊れても約13秒で作り直せる。
- 取り込みはファイルごとに前回読んだバイト位置を覚え、追記分だけを読む。同じレース・同じ馬はキーで1件にまとめ、
  より確定に近いデータ区分だけが上書きする。データ区分 0（提供側の取り消し）は DB からも消す。
- 確認済み（2026-11-13）: 2段階で取り込んだ結果と一括で取り込んだ結果は races・runners とも全行一致。
  追記なしで再実行すると何も変わらない。DB から読んだ `jv_model` の結果はファイルから読んだときと同じ。
- 中止・地方・海外のレースは races に入らない（その出走 439 件は runners にだけ残るが、読み出しは races と結合するので使われない）。

### バックアップ

- データ本体は非公開リポジトリ `mirinnano/keiba-data` のリリースに置く（このリポジトリは公開なので、データは入れない）。
- 2026-11-13: タグ `data-20261113`（JvDump の出力・坂路・netkeiba のデータ。SHA-256 一致を確認済み）。
- 同じタグに `keiba-db-20261113.7z`（`keiba.db` を VACUUM INTO で書き出したもの。レース 20,788・出走 280,403・調教 3,572,698 件）も置いた。
  展開してアプリのデータフォルダか `KEIBA_DB` の場所に置けば、元データから作り直さずに使える。
- 元データからの復元手順はそのリポジトリの README にある。
- 更新したら、新しい日付のタグで差分ではなく丸ごと置く（2GB/ファイルまで）。

## 買い方の検証計画（2026-11-13、結果を見る前に決めた）

アプリの買い目（毎レース本命中心に約 10 点）は回収率 82〜84% で、控除率どおりに負けている。
期待値で買うレースと券種を選べば改善するという仮説を、次の手順で一度だけ確かめる。

**期間の分け方**
- 2011〜2025 年を開発用に使う。2026 年は最終判定用なので使わない。
- 勝率モデルは、評価する年より前のレースだけで当てはめる（年ごとに当てはめ直す）。
- 選ぶ期間: 2016〜2021 年。買い方のルール（券種と期待値の閾値）はここでだけ選ぶ。
- 確かめる期間: 2022〜2025 年。選んだルールを変えずに一度だけ評価する。結果が悪くても、この期間を見てルールを選び直さない。

**候補（これ以外は試さない）**
- 券種: 単勝・馬連・ワイド・3連複。それぞれ「期待値 ≥ 1.0 / 1.1 / 1.2 / 1.3 で買う」か「買わない」。計 4 券種 × 5 通り。
- 選び方: 選ぶ期間で 300 点以上あり、回収率が最も高い閾値。回収率の 95% 区間の上限が 100% に届かない券種は買わない。
- 1 点 100 円の均等買い（配分の工夫は入れない）。

**反証の条件**
- 組み合わせ馬券の的中確率（Harville の補正つき）が実際の的中率と合っていなければ（選ぶ期間で、予測した確率の高い順に 10 等分し、上位の区分で予測と実際が 2 割以上ずれていれば）、その券種の期待値は信用せず買わない。
- 確かめる期間の回収率の 95% 区間の下限が 85% を下回れば、「今の買い目より良い」とは言わない。
- 下限が 100% を超えない限り、「利益が出る」とは言わない。

**分かっている偏り**
- オッズは確定オッズ。締め切り前に買えるオッズでは下がる可能性がある。
- 調教データは 2021 年以降しかないので、2011〜2020 年の馬は調教の特徴量が欠ける（レース内平均で埋まる）。

### 買い方の検証結果（2026-11-14、計画どおり一度だけ）

データ: 2011〜2025 年の JRA 平地 49,916 レース（RACE・坂路は 2011 年から、ウッドは 2021 年 7 月から）。選ぶ期間 19,968 レース、確かめる期間 13,321 レース。

1 回目の実行は、私のシェルのミス（zsh で `--dir` をまとめた変数が分割されなかった）で 2021 年以降の払戻・オッズしか読まれず、選ぶ期間が実質 2021 年だけになっていた。
そのとき確かめる期間の結果も見てしまったが、ルールの選び方は事前に決めた機械的な手順なので、データだけ直してやり直した（1 回目の出力は `backtest/jv_plan_result.bug-only2021.txt`）。

**較正**: どの券種も、予測した的中確率と実際の的中率がよく合っていた（例: ワイド 予測 9.8% / 実際 9.9%、3連複 9.0% / 8.9%、単勝 48.4% / 48.4%）。

**選ぶ期間（2016〜2021）**

| 券種 | 最も良い閾値 | 回収率 [95%区間] | 判定 |
| --- | --- | --- | --- |
| 単勝 | 期待値 ≥ 1.0（6,290 点） | 106.3% [92%, 121%] | 買う |
| 馬連 | 期待値 ≥ 1.0 | 78.6% [71%, 86%] | 買わない |
| ワイド | 期待値 ≥ 1.0 | 66.9% [63%, 71%] | 買わない |
| 3連複 | 期待値 ≥ 1.0 | 71.8% [64%, 80%] | 買わない |

組み合わせ馬券は、確率が較正されていても、期待値 1.0 以上を選ぶと回収率が大きく下がる。
期待値が高く見える組み合わせは、モデルの誤差が市場とずれた方向に出たものが多く選ばれるためと考えられる（推測）。

**確かめる期間（2022〜2025、ルールは単勝・期待値 ≥ 1.0、1 点 100 円）**
- 2,869 点、買ったレース 2,562（全体の 19%）、的中 11.0%、回収率 104.6% [89%, 120%]
- 判定（事前の基準どおり）: 下限 89% は 85% を超えるので「今の買い目（82〜84%）より良い」。下限が 100% を超えないので「利益が出る」とは言わない。
- クラス別: 条件戦 105.8% [90%, 124%]、OP・L 136.7% [56%, 249%]、重賞 45.8% [15%, 85%]（125 点）。
  重賞だけ悪いが、事前に決めた比較ではないので、これを根拠に重賞を外すことはしない（外すなら別の期間で確かめ直す）。
- 確定オッズでの結果なので、締め切り前に買えるオッズでは下がる可能性がある。

**やり直し（調教の基準年の修正後）**: 上の結果を出したあと、2011 年から読むと調教の基準が 2011 年になり、ウッド（2021 年 7 月から）の基準が作られずにウッドの特徴量が消えていたことに気づいた。
基準年を調教の種類ごとに「最初にデータがある年」にして、手順は変えずに一度だけやり直した（修正前の出力は `backtest/jv_plan_result.no-wood-baseline.txt`）。
選ばれたルールは同じ（単勝・期待値 ≥ 1.0、選ぶ期間 106.7% [92%, 122%]）。確かめる期間は 3,221 点、全レースの 21%、回収率 103.1% [90%, 117%]（条件戦 101.4%、OP・L 166.5%、重賞 70.2% [26%, 126%]）。判定は同じで、「今の買い目より良い」が「利益が出る」とは言えない。
アプリにはこのルールを「おすすめ」の印として入れた（2026-11-14）。買い目そのものは持ち主の希望で従来どおり印から組み（期待値に関係なく買う）、
期待値 1.0 以上の単勝（JRA-VAN モデル・実オッズ）だけに「おすすめ」、ほかには「おすすめしない」を付ける。おすすめの単勝は最低 100 円。
参考: 従来の買い目全体の回収率は 82〜84%（上の「アプリの買い目のバックテスト」）。

### アプリの係数を 2012〜2025 年で当てはめ直した（2026-11-14）

アプリの係数（`jv_coef.rs`）は 2021〜2025 年の 16,650 レースで当てはめていたが、買い方の検証は 2012 年からのデータで年ごとに当てはめたモデルで行った。
両者を揃えるため、2012〜2025 年の 46,585 レースで当てはめ直した（`jv_model -- <keiba.db> --from 2011 --export src/jv_coef.rs`、2011 年は履歴の立ち上がりなので学習に使わない）。
特徴量の定義を揃えるため、アプリの Engine も 2011 年から履歴を読む（`jvmodel::HISTORY_FROM`）。基準タイムは 2011 年、調教の基準は坂路 2011 年・ウッド 2021 年で作る。
Engine の初回構築は 6.4 秒から 8.4 秒になった（同じ日のうちは使い回す）。
新しい係数には確かめる期間（2022〜2025）も含まれているので、この係数の成績をその期間で測り直すことはしない（2026 年の最終判定で測る）。

## 複勝の検証計画（2026-11-14、結果を見る前に決めた）

単勝の検証と同じ手順で、複勝を候補に足して一度だけ確かめる。複勝の結果はまだ一度も見ていない。

- 的中確率: 出走 8 頭以上は Harville（補正つき）の 3 着内確率、7 頭以下は 2 着内確率。5 頭以下（複勝の発売なし）は対象外。
- オッズ: 確定の複勝オッズの下限（O1、保守的な見積もり）。期待値 = 的中確率 × 下限オッズ。
- 払戻: HR の複勝払戻。
- 候補: 期待値 ≥ 1.0 / 1.1 / 1.2 / 1.3 で買う、または買わない。選び方・期間（選ぶ 2016〜2021、確かめる 2022〜2025）・反証の条件（較正のずれ 2 割、区間の下限 85% / 100%）は単勝のときと同じ。
- 複勝は単勝と別に判定する（単勝のルールは変えない）。

**結果（2026-11-14）: 不採用。** 選ぶ期間で期待値 ≥ 1.0 の複勝は 6,393 点・回収率 46.8% [39%, 55%]（閾値を上げるほど悪化）。区間の上限が 100% に届かないので「買わない」。確かめる期間では評価していない。
較正は、上位（確率の高い）区分では合っていた（予測 57.2% / 実際 55.6%）が、人気薄の区分では 3 着内確率を約 2 倍に見積もっていた（予測 1.9% / 実際 0.9%）。期待値 ≥ 1.0 で選ぶと、この過大評価された人気薄ばかりを拾う。
事前に決めた較正の判定は上位 2 区分だけを見ていたので、このずれを拾えなかった。今後の較正の判定は、実際に買う候補が集まる区分で行う。

## 当日の馬場の偏りの検証計画（2026-11-14、結果を見る前に決めた）

同じ日・同じ競馬場・同じ馬場（芝/ダ）で、そのレースより前に終わったレースの結果から、馬場の偏りを測って特徴量にする。

- 内外の偏り: 先に終わったレースの各馬について、馬番の位置（馬番/頭数）と着順率の相関の符号つきの強さ（内 1/3 の平均着順率 − 外 1/3 の平均着順率）。特徴量 = 偏り × (この馬の馬番位置 − 0.5)。
- 前後の偏り: 4 角の位置（4 角順位/頭数）が前 1/3 の馬の平均着順率 − 後ろ 1/3 の平均着順率。特徴量 = 偏り × (この馬の過去 3 走の 4 角位置の平均 − 0.5)。
- 先に終わったレースが 2 つ未満なら欠け（レース内平均で埋まる）。
- 評価: 2011 年から読み、従来の時系列ローリング検証（8 区間のうち後半 4 区間）で、「市場＋採用中の特徴量＋当日の 2 つ」と「市場＋採用中の特徴量」の 1 着の対数損失を比べる。
- 採用の条件: 差の 95% 区間の上限が 0 未満（確かに良い）。それ以外なら採用しない。これ以外の作り方は試さない。
- アプリで使うには、当日の先のレースの結果を取り込む仕組みが別に要る（DB は週 1 回の更新なので）。採用になってから作る。

**結果（2026-11-14）: 事前の条件は満たした（ぎりぎり）。** 2011 年から読んだ時系列ローリング検証（後半 24,956 レース）で、
上積みは −0.0003 [−0.0005, −0.0000]。区間の上限は 0 をわずかに下回った。
ただし大きさは、採用中の特徴量全体の改善（−0.0061）の 5% ほどしかない。アプリで使うには当日の先のレースの結果を取り込む仕組みが要るので、作るかどうかは別に決める。
持ち主の判断でアプリに入れた（2026-11-14）: 採用中の列（ADOPTED）を 40 列にし、2012〜2025 年で係数を当てはめ直した（どちらの係数も正。内が有利な日は外枠の馬を、前が有利な日は後ろから行く馬を下げる向き）。
アプリは、同じ日・同じ場で先に終わったレースの結果を DB から読み、DB になければ netkeiba の結果ページ（馬場・着順・通過の最後の数）から取る（1 秒に 1 件まで、確定したものは使い回す）。先のレースが 2 つ未満なら使わない。
「おすすめ」の買い方（期待値 1.0 以上の単勝）は、この 2 つを入れる前のモデルで検証したもので、入れた後の成績はまだ測っていない（2026 年の最終判定で測る）。

## 道悪の向き不向きの検証計画（2026-11-14、結果を見る前に決めた）

今のモデルは、その日の馬場状態（良・稍重・重・不良）を使っていない。雨の日に、道悪で走れる馬とそうでない馬の差を足せるかを確かめる。

- 特徴量は 1 つだけ（列 49「道悪×道悪実績」）。その日の馬場（芝なら芝の状態、ダートならダートの状態）が稍重以下のときだけ値を持ち、良なら 0。
  値 = 同じ馬場（芝/ダ）の過去走のうち稍重以下での 3 着内率 − 同じ馬場の全過去走での 3 着内率（どちらもロジットで、事前 0.25・強さ 3 で縮める）。
  稍重以下を走ったことがなければ欠け（レース内平均で埋まる）。
- 評価: 2011 年から読み、時系列ローリング検証（8 区間のうち後半 4 区間）で、「市場＋採用中の 40 列（ADOPTED）＋列 49」と「市場＋採用中の 40 列」の 1 着の対数損失を、対応のあるブートストラップで比べる。
- 採用の条件: 差の 95% 区間の上限が 0 未満。それ以外なら採用しない。これ以外の作り方（重の程度で重みを変える、父の道悪成績を足す、など）は、この結果を見てから試さない。
- 道悪のレースは全体の 2〜3 割なので、全体の平均で見ると差は小さく出る。参考として、その日が稍重以下のレースだけの差も出すが、判定には使わない。

**結果（2026-11-14、計画どおり一度だけ）: 採用しない。** `jv_model -- <keiba.db> --from 2011 --wet`、後半 4 区間 24,956 レース。
(+道悪) − 採用中 = +0.0000 [−0.0000, +0.0001]。4 区間とも差は ±0.0001 以内で、係数は小さな正（+0.004〜+0.012）。
参考の稍重以下のレースだけ（6,658 レース）でも +0.0001 [−0.0001, +0.0003] で、良くならない。
その馬の道悪での成績は、単勝オッズにすでに織り込まれているか、走った数が少なすぎて当てにならないと考えられる（どちらかは切り分けていない）。
列 49 は特徴量として作り続けるが、採用中の列（ADOPTED）には入れない。アプリの勝率は変わらない。

## 学習に使う年数の検証計画（2026-11-14、結果を見る前に決めた）

2011 年より前のデータを取り足す価値があるかを、手元のデータで先に確かめる。

- 確かめる期間を 2023〜2025 年に固定し、学習に使う期間だけを変える: 直近 5 年（2018〜2022）、8 年（2015〜2022）、11 年（2012〜2022）。
- モデルは市場＋採用中の 40 列（ADOPTED）、L2 0.1。1 着の対数損失を、対応のあるブートストラップで比べる。
- 判定: 「11 年 − 8 年」の 95% 区間の上限が 0 未満なら、年数を増やすとまだ良くなっているので、2011 年より前を取り足す価値がある。そうでなければ取り足さない。
- 「11 年 − 5 年」「8 年 − 5 年」は傾きを見る参考で、判定には使わない。

**結果（2026-11-14、一度だけ）: 取り足さない。** `jv_model -- <keiba.db> --from 2011 --years`、確かめる期間 9,991 レース。
1 着の対数損失は 5 年 1.91178 / 8 年 1.91124 / 11 年 1.91116。
判定の「11 年 − 8 年」は −0.00008 [−0.00045, +0.00030] で 0 を含む。参考の「8 年 − 5 年」は −0.00054 [−0.00104, −0.00003] で確かに良い。
5 年から 8 年までは年数を増やすと良くなり、8 年から 11 年ではほぼ頭打ち。2011 年より前を足しても、さらに良くなる見込みは小さい。

## 組み合わせの確率に市場を混ぜる検証計画（2026-11-14、結果を見る前に決めた。ADR-001 の A）

組み合わせ馬券の確率は、今はモデルの勝率から補正つき Harville で作るだけで、組み合わせのオッズに入っている市場の見方を使っていない。
単勝と同じく、市場とモデルをロジットの空間で混ぜる。

- 対象: 馬連・ワイド・3連複。勝率モデルは従来の買い方の検証と同じく、年ごとにその年より前（2012 年〜）で当てはめ直したもの。
- 市場の確率: その券種の全組み合わせについて 1/確定オッズ を取り、合計が 1（ワイドは 3）になるように割り戻す。オッズのない組み合わせは除く。
- 混ぜた確率: 組み合わせ c について s_c = α・log(市場の確率) + β・log(モデルの確率)、券種ごとに softmax を取り、ワイドは 3 倍する。
- α・β は券種ごとに、選ぶ期間（2016〜2021）の的中した組み合わせの対数尤度が最大になるように当てはめ、確かめる期間では固定する。

**判定 1（アプリに入れるか）**: 確かめる期間（2022〜2025）で、的中した組み合わせの対数損失（レースごと）を、
「混ぜた確率」と「モデルだけ（今のやり方）」で、対応のあるブートストラップで比べる。差の 95% 区間の上限が 0 未満の券種は、アプリの組み合わせの確率と期待値を混ぜた確率に替える。
参考として「市場だけ」との差も出す（判定には使わない）。

**判定 2（買う組み合わせのルール）**: 従来の買い方の検証と同じ手順。混ぜた確率 × 確定オッズ ≥ 1.0 / 1.1 / 1.2 / 1.3 を候補に、
選ぶ期間で 300 点以上あって回収率が最も高い閾値を選ぶ。その回収率の 95% 区間の上限が 100% に届かない券種は買わない。
確かめる期間で一度だけ評価し、下限が 85% を超えれば「今の買い目より良い」、100% を超えれば「利益が出る」と言う。

- これ以外の混ぜ方（券種をまたいで重みを共有する、オッズの非線形を足す、など）は、この結果を見てから試さない。
- 確定オッズでの計算なので、締め切り前に買えるオッズでは下がる可能性がある。

## 開発用と最終判定用の分け方

- **開発用**：2021〜2025年のレース。特徴量・正則化・閾値の選び直しはここでだけ行う。
- **最終判定用（ホールドアウト）**：2026年1月以降のレース。モデルを決め切るまで**集めない・見ない**。
  決めたら一度だけ集めて一度だけ評価する。結果が悪くても、そのデータで作り直してもう一度、はしない。
- 締め切り前オッズの記録（2026-11-14〜）は最終判定用の期間にあたる。記録はするが、最終判定まで中身を評価に使わない
  （取れているかの件数確認だけはしてよい）。

## 開発用での評価（`cargo run --release --example backtest -- <races.jsonl>... [--horses <horses.jsonl>]`）

- 日付順に8区間に分け、k 区間目まで学習・k+1 区間目で検証（k=4..7）。
- 基準タイム・騎手・ペース基準は学習側の過去走だけ、父の成績はそのレースより前の結果だけで作る。
- 主な指標は1着の対数損失。比べる相手は「市場（γ補正）」= 単勝オッズの勝率を γ 乗したもの。
- 特徴量を採用する条件：**市場＋特徴量が市場（γ補正）より、4区間すべてで良い**こと、かつ
  **検証全区間をまとめたレース単位の対応のあるブートストラップで、差の95%区間が 0 を含まない**こと（2026-11-12 追加）。
- 回収率は参考値。確定オッズで計算しているので、実際より有利に出ている可能性がある。

## 最終判定（ホールドアウトで一度だけ）

次をすべて満たしたら「市場に勝てる見込みがある」と言ってよい。

1. 市場＋モデルの1着対数損失が、市場（γ補正）より小さい。
2. 締め切り3分前のオッズで「期待値 ≥ 閾値」の単勝を買ったときの回収率について、
   ブートストラップ（レース単位で再標本化）の95%区間の下限が 100% を超える。閾値は開発用データで先に決めておく。
3. 2 の買い目が 1,000 点以上ある。

満たさなければ「公開情報のこの使い方では勝てない」が結論。それも記録する。

## 開発用データでの所見（2023〜2025年 1518レース, 2026-11-12 時点）

- 1着の対数損失（4区間平均）: 市場 1.8783 / 市場（γ補正）1.8767 / 市場＋モデル 1.8746。市場＋モデルは4区間すべてで市場（γ補正）より良い。
- ただし市場と一緒に当てはめたモデルの重み δ は **4区間すべてで負（−0.09〜−0.10）**。
  市場を知った上では、モデル（＝公開されている成績の要約）が高く評価する馬ほど買われすぎている、という意味。
  特徴量ごとに見ても、能力・適性・斤量・指数（最高）は負、指数（平均）・騎手・父・前走の着差・前走人気は正で、区間をまたいで符号が揃う。
- γ は 1.09〜1.11（>1）。単勝オッズのままだと人気馬をやや低く、人気薄をやや高く見ている。
- 期待値 ≥ 1 の馬は検証区間に一頭もいない。期待値 ≥ 0.8 の単勝の回収率は 85.0%（2,030点, 確定オッズ）。
- 当日の馬場の偏り（同日・同場の前のレースの内外・前後）は上積みなし。
- **訂正（同日, 対応のあるブートストラップ）**: 検証全区間 756 レースをまとめると、
  市場＋モデル − 市場（γ補正）= −0.0021、95%区間 [−0.0054, +0.0014]。**0 を含むので有意ではない**。
  「4区間すべてで良い」は弱い証拠だった。γ補正も [−0.0043, +0.0010] で有意ではない。
- 1〜3着の順序（Plackett-Luce）で学習すると、1着の対数損失は有意に悪化した（+0.022 [+0.010, +0.036]）。
  2・3着を同じ効用で扱うと、2・3着の決まり方の違い（Harville の偏り）を勝率側に持ち込むため。採用しない。
- 0.002 程度の差を検出するには、検証用のレースが今の約4倍（3,000レース程度）必要。
  採用条件に「対応のあるブートストラップの95%区間が 0 を含まない」を加える。

## JRA-VAN の全レースでの所見（2021〜2025年 平地 16,650レース, 2026-11-13）

- データ: JvDump で取得した RA/SE を `jv_build` で重複除去（確定成績を優先）。netkeiba の 21,016 頭と突き合わせ、
  着順・タイム・単勝オッズ・枠・上がり3F は 100%、斤量 99.99% 一致。
- 検証は時系列8区間のうち後半4区間（8,324 レース）。95%区間の幅は約 ±0.0004 で、netkeiba の標本（±0.0035）より約10倍細かい。
- **JRA-VAN のマイニング予想（順位・予想タイム）は市場に上積みなし**: +0.0000 [−0.0004, +0.0005]。係数はわずかに負。
  JRA-VAN 利用者向けの予想も、すでにオッズに織り込まれている。
- 期待値 ≥ 1.0 の馬は検証区間に一頭もいない（市場＋マイニングでも同じ）。

## 自前の特徴量（JRA-VAN 全レース, `jv_model`, 2026-11-13）

- 30個の特徴量を、そのレースより前の日付のデータだけで作った（日付ごとに特徴量を作ってから、その日の結果を履歴に足す）。
  基準タイムとペースの基準は 2021年だけで作る。過去走のある馬は 86.6%（2021年初めは履歴がない）。
- 1着の対数損失（検証 8,324 レース）: 市場 1.9117 / 市場（γ補正）1.9113 / モデルのみ 2.1341 / **市場＋全特徴量 1.9088**。
- **市場＋全特徴量 − 市場（γ補正）= −0.0026 [−0.0048, −0.0004]**。4区間すべてで良く、95%区間が 0 を含まない。
  採用条件を初めて満たした。
- グループ別で有意: 着順・着差 −0.0016 [−0.0028, −0.0005]、その他（馬齢・馬番・脚質・同場/同距離成績）−0.0017 [−0.0032, −0.0004]。
  時計・上がり展開・過去人気・クラス・騎手調教師・状態ローテは単独では有意でない。
- 市場と一緒に当てはめた係数は大半が4区間で符号一致。市場は「前走の好走・前走の人気・高齢・上位騎手・同場/同距離の好成績」を
  買いすぎ、「騎手の格上げ・クラス変化・休み明け・距離/芝ダ変更・馬体重・上がり・ブリンカー」を軽く見ている。
  つまり、直近の成績と評判に反応しすぎ、変化を織り込み切れていない。
- ただし儲かる水準ではない: 期待値 ≥ 1.0 の単勝 88.6%（1,233点）、≥ 1.1 で 97.6%（170点）。どちらも確定オッズ。
- 注意: グループ別の比較は8つ同時に見ているので、単独で有意なグループには多重比較の分だけ割り引いて考える。
  主要な比較（市場＋全特徴量）は事前に決めていたもの。

### 調教の詳細を試して不採用（2026-11-13）

  符号が揃うことは、検証で良くなることの証明にならない（係数の推定ぶれが増えて、検証では損をした）。採用しない。
- 途中、比べる列を取り違えて「詳細は有意に良い」と出した。比較の添字を直して確認した（`jv_model.rs` にどの列が何かを明記）。

正則化の強さ、市場の非線形（オッズの二乗・頭数との積）、指数との積、主な特徴量の二乗を、採用中のモデルと比べた（`jv_model -- <keiba.db> --explore`）。

| --- | --- |
| L2 0.03 | −0.0002 [−0.0004, −0.0000] |

| L2 0.3 | −0.0007 [−0.0017, +0.0004] |

### 指数の内訳（重み）を自動にした（2026-11-13）

手動の重みスライダーをやめ、モデルの係数から各要素（能力・時計・適性・騎手・枠・展開・調教）の寄与を出すようにした。
表の各要素は、その要素の寄与をレース内の偏差値にしたもの。
JRA-VAN モデルでは、寄与を「オッズを使わないモデル」の係数で出す（市場モデルの係数はオッズに対する上積みなので、強さとしては読めないため）。勝率は従来どおり市場モデルで出す。

### アプリの買い目のバックテスト（2026-11-13）

アプリと同じ買い目の組み方（単勝・馬連・ワイド・3連複、予算 3000 円）を、検証区間 8,324 レースで作り、JRA-VAN の払戻（HR）で精算した（`jv_model -- <keiba.db> --bets <out/RACE>`）。
勝率はそのレースより前の区間だけで当てはめたモデル、組み合わせのオッズは確定オッズ（O2・O3・O5）を使った。

| 配分 | 回収率 [95%区間] | 何か的中したレース | プラス収支のレース |
| --- | --- | ---: | ---: |
| バランス | 82.4% [80%, 85%] | 58% | 32% |
| 的中重視 | 82.3% [80%, 84%] | 58% | 36% |
| 期待値重視 | 83.7% [81%, 86%] | 57% | 31% |

重賞（322 レース）も 80〜83% で、ほかのクラスと区別できない。
買い目は毎レース本命中心に組むので、控除率（単勝 20%、馬連・ワイド・3連複 22.5%）をほぼそのまま負けている。
期待値 1.0 以上の単勝だけを買った場合（106.9%、1,458 点）との差は、モデルの差ではなく、買うかどうかの選び方の差である。

## 既知の弱点

- 開発用の回収率は確定オッズで計算している（締め切り前オッズの記録は 2026-11-14 から）。
- レースは各月15日前後の土日、月1〜2日分だけを取っている。季節や開催場の偏りは未確認。
- 開発用データで何度も選び直しているので、開発用の数字は楽観的に出ていると考える。
- 買い目の組み方（◎-○ など）と金額の配分は手で決めたまま。データで確かめたのは単勝だけ。
